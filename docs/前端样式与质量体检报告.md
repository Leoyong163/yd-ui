# 权限自助门户 · 前端样式与质量体检报告

> 审计对象：`D:\demo\grok\权限自助门户demo\vue代码包`（Vue 3.5 + Vite 6 + ant-design-vue 4 + Tailwind v4）
> 审计时间：2026-09-20
> 审计方式：源码审读 + **真实浏览器实测**（Chrome headless，`getBoundingClientRect()` / `getComputedStyle()`），覆盖 **5 个导航页 × 3 个视口 × 亮/暗双主题 + 7 个流程表单页 + 审批详情**，共 30+ 组采样
> 本报告只记录问题与改法，**未改动任何业务代码**。

## 一、总评

| # | 维度 | 分数 | 关键发现 |
|---|------|:----:|----------|
| 1 | 无障碍 (A11y) | 2 / 4 | 暗色下出现「白底白字」（实测 **1.11:1**）；亮色下约 **325 处**小字不达 AA，但改 2 个 token 即可全站修复 |

**评分口径**：每维 0–4 分。0–5 Critical / 6–9 Poor / 10–13 Acceptable / 14–17 Good / 18–20 Excellent。

**一句话结论**：这个项目的问题不是「做得烂」，而是**同一个东西被做了两遍、三遍**——两套 token、两套暗色机制、两套断点、兜底值又各写一遍。真正要修的地方集中在少数几个源头，而不是散落几百处。最典型的证据：亮色下 325 处对比度不达标，根因只是 `--text-muted` 一个值偏灰；暗色下整块表格不可读，根因只是 4 个文件里的内联 `background-color`。

| 元素 | 前景色 | 背景色 | 实测对比度 |

### P1 —— 发布前应修

#### P1-1 暗色下主色按钮文字对比度不足（每个表单页的「提交」都中）

- **实测**：`rgb(255,255,255)` on `rgb(77,148,255)`（暗色 `--primary`）= **3.0 : 1**，字号 12–14px。
- **覆盖**：7 个表单页的「提交」按钮、首页待办表「去处理」（5 处）、审批详情「搜索」「同意」。
- **改法**：暗色下 `--primary` 作按钮底时再压深一档（例如 `#3a7fe0`），或按钮文字统一走 `var(--text-inverse)` 语义色并同步调整底色。

#### P1-2 暗色下 `--danger` 按钮对比度不足

- **实测**：`rgb(255,255,255)` on `rgb(248,113,113)`（暗色 `--danger`）@13px = **2.77 : 1**。
- **位置**：审批详情「驳回」按钮。
- **改法**：暗色 `--danger` 调深（`#e05555` 一档）。

#### P1-3 `--info` / `--info-soft` 没有暗色覆盖（token 漏项）

- **事实**：`src/styles/demo1/variables.css` 的 `[data-theme="dark"]` 块（第 157–207 行）覆盖了 `--primary` `--cyan` `--purple` `--success` `--warning` `--danger` —— **唯独漏了 `--info`**。
- **实测**：暗色下 `rgb(20,86,240)`（即亮色 `--info: #1456F0`，未反转）on `rgb(18,26,43)` = **3.0 : 1**，出现在 7 个表单页的「预览」「下载」文字上。
- **改法**：暗色块补 `--info: #4d8cff;` 与 `--info-soft: rgba(77,140,255,0.14);`。

#### P1-4 硬编码浅色底破坏暗色主题（内联 + 组件岛屿）

- **`.post-label-date-*` 整块是「antd 原始色板岛屿」**：`src/styles/demo1/pages.css:3988–4141` 整套用了 `#d9d9d9` 边框、`#1677ff` 选中态、`rgba(0,0,0,0.88)` 文字、`rgba(0,0,0,0.25)` 占位符、`#f5f5f5` hover —— 完全绕开 token 体系。暗色下这套文字是**黑字**。
- **`.approval-perm-table` 用 Tailwind 默认色板**：`pages.css:3235–3431` 的 `#E5E7EB` `#F9FAFB` `#364153` `#1E2939` `#F3F4F6`（上一次修「系统角色授权表」时已确认这类硬编码在暗色下不成立）。
- **实测（暗色）**：`span` 「删除」= `rgba(0,0,0,0.25)` on white = **1.83 : 1**。
- **改法**：这两块统一换成 `var(--border)` / `var(--surface-3)` / `var(--text)` / `var(--text-muted)` / `var(--primary-soft)`。

#### P1-5 暗色下禁用态控件仍是浅灰底

- **位置**：`pages.css:1712`（`.role-single-select:disabled`）、`pages.css:1851`（`.inline-search-select.is-disabled .inline-search-select-input`），都是 `background: #edeeee`。
- **实测（暗色）**：`input.inline-search-select-input` = `rgb(237,238,238)`，宽 902px —— 深色页面上浮着一大块浅灰。
- **改法**：`#edeeee` → `var(--bg-muted)`（暗色下自动变深）。

#### P1-6 单 JS 包 1.78 MB，无任何代码分割

- **实测产物体积**：

| 文件 | 大小 |
|---|---|
| `dist/assets/index-*.js` | **1,818.7 KB** |
| `dist/assets/index-*.css` | 173.3 KB |
| `dist/assets/img_banner-*.png` | 128.3 KB |
| `dist` 合计 | 2,182.6 KB |

- **根因**：`src/App.vue:11–22` **静态 import 了全部 12 个页面组件**，叠加 antd 全量引入与 dayjs。
- **改法**：页面组件改 `defineAsyncComponent` 按页懒加载（`src/RootShell.vue:5` 已经用这个模式处理 Inspector，照抄即可）；antd 改按需引入。首屏只需要 `Home`。
- **预期**：首屏 JS 可降到 400 KB 量级。

#### P1-7 全局 MutationObserver 在每次 DOM 变更时做全文档查询

- **位置**：`src/App.vue:81–98`
- **代码事实**：`observer.observe(document.body, { childList: true, subtree: true })`，回调里执行 `document.querySelectorAll('.ant-form-item-label > label[title]')`。
- **影响**：Vue 每次渲染、每个列表项更新都会触发一次全文档 `querySelectorAll` —— 表格页与表单页受影响最直接。
- **改法**：目标只是去掉 antd 自动加的 `title`。优先级从高到低：(1) 在模板侧不生成该 `title`；(2) 把 observer 范围收到表单容器并在首次匹配后 `disconnect()`；(3) 保留但加 `requestIdleCallback` 节流。

#### P1-8 两套设计 token 体系同名冲突，后加载的一套静默胜出

- **事实**：`src/styles/theme.css`（Tailwind v4 + shadcn 体系）与 `src/styles/demo1/variables.css` 定义了**同名但不同值**的 token：

| token | `theme.css` | `demo1/variables.css` |
|---|---|---|
| `--primary` | `#030213`（近黑） | `#1678ff`（品牌蓝） |
| `--border` | `rgba(0,0,0,0.1)` | `#DEE0E3` |
| `--radius` | `0.625rem`（10px） | `8px` |
| `--radius-sm` | `calc(var(--radius) - 4px)` | `6px` |
| `--font-mono` | Tailwind 默认 | `"SF Mono", Menlo, …` |
| `--text-xs/sm/base/lg/xl/2xl/3xl` | Tailwind 字阶 | 映射到 `--fs-*` 自定义字阶 |

- **加载顺序**（`src/index.css:1–11`）：`fonts → tailwind → theme` 在前，`demo1/*` 在后。**且 demo1 的 CSS 全部是非分层 CSS，而 theme.css 的规则包在 `@layer base` / `@layer utilities` 里** —— 按 CSS 层叠层规则，**非分层永远赢过分层**。
- **已产生的静默后果**（不是假设，是当前行为）：
  1. `theme.css:81–120` 的 `@theme inline` 把 `--color-primary` 映射到 `var(--primary)`，实际拿到的是 demo1 的**蓝** `#1678ff`，而不是 shadcn 本意的近黑；
  2. `theme.css:137` 的 `html { font-size: var(--font-size) }`（16px）被 `base.css:8` 的 `html { font-size: 14px }` 覆盖 —— 实测所有视口根字号都是 **14px**（见 P2-6）；
  3. `theme.css` 的 `@layer base` 里给 `h1`–`h4`、`p`、`label`、`button`、`input` 定义的所有排版规则，**一律输给** `base.css:46–83` 里 demo1 的同名规则。
- **改法**：二选一，别维持现状。(A) 保留 demo1 作为唯一体系，把 `theme.css` 削成纯 preflight（只留 `@import 'tailwindcss'` 与 `@theme inline` 里真正需要的映射），删掉所有会被覆盖的 token 定义；(B) 若将来真要上 shadcn，给两套 token 加前缀区分。**推荐 A**。

#### P2-5 Tailwind v4 与 tw-animate-css 全程空转

- **事实**：全项目 `.vue` 模板中 **0 处**使用 Tailwind 工具类（grep `class="…flex|grid|p-4|text-sm|rounded…"` 只命中 `bg-grid`、`flow-grid`、`detail-grid` 等 demo1 自有类名）。
- `src/styles/tailwind.css:4` 引入了 `tw-animate-css`，但 `animate-*` 类 **0 处**使用。
- `theme.css:1` 的 `@custom-variant dark (&:is(.dark *))` 和 `theme.css:44–79` 的整个 `.dark { … }` 块（30 余个暗色 token）**永远不会生效** —— 主题切换走的是 `src/Shell.vue:33` 的 `document.documentElement.setAttribute('data-theme', t)`，从不添加 `.dark` 类。
- **改法**：删掉 `theme.css` 的 `.dark` 块与 `tw-animate-css`；`theme.css` 按 P1-8 的方案 A 削成纯 preflight。

#### P2-6 根字号 14px 会让 Tailwind 的 rem 工具类整体缩水

- **实测**：所有页面 × 所有视口，`html` 计算字号恒为 **14px**（来自 `base.css:8`，覆盖了 `theme.css:137` 的 16px）。
- **影响**：Tailwind v4 的间距/尺寸工具类以 `1rem = 16px` 为前提，这里会**缩水 12.5%**（`p-4` 算出 14px 而非 16px）。当前模板没用工具类（见 P2-5），所以是**埋雷**而非现症；一旦有人开始写 `class="p-4"` 就会踩。
- **改法**：把 14px 从 `html` 移到 `body`，或显式加注释声明「根字号已改为 14px」。

#### P2-8 z-index 两套基准并存

- token 层定义了 `--z-sidebar:100 / --z-overlay:200 / --z-dropdown:300 / --z-modal:400 / --z-toast:500`，`components.css` 与 `layout.css` 确实在用（共 14 处）。
- 但 `pages.css` 另有硬编码：`z-index: 1050`（1729、1958）、`1200`（3159、4065）、`50`（4331）、`30`（1908）—— **全部高于 token 梯度的最高档 500**，会让这些浮层压过 `--z-toast`。
- `devtools/Inspector.vue` 的 `2147483000/2147483002` 属 dev-only，可接受。
- **改法**：把 1050/1200 这类值并入 token 梯度（新增 `--z-sheet: 600` 之类），或至少统一到最高档以下。

#### P2-9 `transition: all` 5 处

- `pages.css:1063`、`pages.css:4000`、`pages.css:4095`、`components.css:741`、`components.css:1039`
- **改法**：明确列出要过渡的属性。`transition: all` 会连 `width`/`height`/`padding` 一起过渡，属于「动画化布局属性」，会掉帧。

#### P2-10 12 个断点值，语义重叠

- 实测存在的断点：`480` `640` `720` `768` `900` `1100` `1101` `1180` `1200` `1201` `1280` `1460`
- 其中 `720` 与 `768`、`1100/1180/1200` 承担相近职责，`1101`/`1201` 是为了绕开 `max-width: 1100`/`1200` 而生的补丁式反向断点。
- **改法**：收敛成 4 档（例如 `480 / 768 / 1100 / 1440`），按 4px 间距梯度同理定一套命名。

## 三、系统性问题（比单条缺陷更值得处理）

1. **同一件事被做了两遍**：两套 token（`theme.css` / `variables.css`）、两套暗色机制（`.dark` / `[data-theme]`）、两套断点语义（720/768、1100/1180/1200）、两套 z-index 基准（token 梯度 / 硬编码 1050、1200）。P1-8 是这一类里影响最大的。
2. **硬编码色值绕开 token，约 120 处 + 13 个组件内联**：`pages.css` 74、`components.css` 40、`layout.css` 6，另有 13 个 `.vue` 文件模板里带内联色（`role-form/ExpandedRowDetails.vue` 单个文件 32 处最多）。**所有暗色主题可见缺陷都可以追溯到这里** —— 暗色的失败不是暗色本身的问题，是硬编码没跟着反转。
3. **真正需要改的源头很少**：325 处对比度问题 = `--text-muted` 一个值；暗色不可读 = 4 个文件的内联 `background-color`；1.78MB 包 = `App.vue` 的 12 行静态 import。**先改源头，别逐条打补丁。**

## 四、做得好的地方（请保持并复用）

- **无障碍基础扎实**：全局 `:focus-visible` 轮廓（`base.css:112–117`）、`prefers-reduced-motion` 与 `data-reduced-motion` 双通道（`base.css:29–44`）、`.sr-only` 工具类、`main` 带 `tabindex="-1"`、侧栏图标按钮都有 `aria-label`（`Shell.vue:161/166/169/178/198/202`）、`aria-expanded`/`aria-haspopup` 用得到位。
- **实测零缺陷项**：0 张图片缺 `alt`、0 个输入缺标签或占位、0 个可点击 `div` 缺键盘可达、0 个重复 `id`。这三项很多项目做不到。
- **页面级无横向溢出**：5 页 × 3 视口全部 `scrollWidth === clientWidth`，说明外层栅格是稳的。
- **暗色主题覆盖面广且质量优于亮色**：暗色下每页仅 1–5 处对比度问题（亮色 26–69 处），因为 `--text-muted` 的暗色值 `#7d8ca3` 是对的选择。
- **有 `@media print`**（`pages.css:3977–3985`），给打印做了收边；**有 4px 间距梯度**（`--space-2xs … 3xl`）；**有完整的 `--z-*` 渐变**（虽然 pages.css 没遵守）。
- **dev-only 代码已做隔离**：`RootShell.vue:5` 用 `import.meta.env.DEV` + `defineAsyncComponent` 挂 Inspector，产物里不会带上。
- 全局设计意图清晰：`variables.css:1` 明确写了「spacing 4px base」，`base.css:46` 写了「Heading roles: page 24/600 · section 20/500 …」—— 有体系、有注释，这在还原类项目里不多见。

## 五、建议执行顺序

按「改动量 / 收益比」排序，前 4 步做完，报告里 P0 与 P1 就清空了：

1. **修暗色可见性**（P0-1、P1-4、P1-5）：4 个文件的内联 `background-color` + 一个 `#edeeee` → 换成 token，约 10 行改动。
