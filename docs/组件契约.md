# 组件库契约（@yd/ui）

> 本文是 **P0-T7 的产出**，也是库与宿主之间的运行时合同。
> 任何引用本库的项目，都必须满足本文的约定；否则会出现「引到了组件、外观却是错的」这类静默降级。
>
> 状态：P0 定稿 · 生效阶段 P1

---

## 1. 落地位置与引用方式（A 案：源码直引）

| 项 | 决定 |
| --- | --- |
| 库根目录 | `D:\demo\组件库` |
| 库包名 | `@yd/ui`（`private: true`，首期不发 registry） |
| 引用方式 | 宿主 Vite `resolve.alias` 指向库的 **源码** `src`，不走构建产物 |
| 是否需要同步步骤 | **不需要**。宿主读的就是库源码，改完即时生效（HMR 直通） |

**为什么选 A 案**：它已满足「单独引用 + 可增删改 + 改完同步」的全部诉求，且零构建成本、零版本管理。
交给其它项目复用、或需要脱离本机运行时，再升级为 workspace 包（库内代码不动，只改两处配置）。

### 1.1 宿主侧必须的两处配置

`vite.config.ts`：

```ts
import path from 'path'

resolve: {
  alias: {
    '@': path.resolve(__dirname, './src'),
    '@yd/ui': 'D:/demo/组件库/src',
  },
},
server: {
  // 库在宿主工作区之外，Vite 默认拒绝服务工作区外的文件，必须显式放行
  fs: { allow: [path.resolve(__dirname), 'D:/demo/组件库'] },
},
```

`tsconfig.json`：

```json
"paths": {
  "@/*": ["./src/*"],
  "@yd/ui": ["../组件库/src/index.ts"]
}
```

> 这两处是**跨盘引用的必要条件**。缺 alias 会构建报错，缺 `fs.allow` 会 dev server 报 403。

### 1.2 库的出口（`src/index.ts`）


## 2. 依赖边界（硬约束）

库**不得**出现以下三类依赖。这条是「库能否被别的项目复用」的分水岭。

| 禁止 | 原因 | 反例（当前宿主中存在，搬迁时必须拆掉） |
| --- | --- | --- |
| 依赖宿主的 `@/` 别名 | 库一旦引用宿主路径，就永远无法单独交付 | `KpiImg` → `../shared` 取 `KPI_ASSETS` |
| 依赖宿主业务规则 | 业务阈值会变，库不该跟着变 | `riskLevel(days)` 的 3 天 / 7 天阈值 |
| 依赖宿主页面结构 | 页面类名是宿主私有语义 | `PermissionTree` 依赖 `.form-auth-preview .tree-*` 上下文 |

**允许**的依赖：`vue`、`ant-design-vue`（见 §4）、库自身的资源文件。

判据（决定某个东西该不该进库）：**≥ 2 个使用方 + 与业务语义无关**。只服务一个页面的东西留在页面里才是对的。

## 3. 运行时合同

### 3.1 样式：必须由宿主按序引入，且顺序不可调

库**不带任何自动注入**的样式。宿主必须在自己的样式入口里按以下顺序 import：

```css
/* 宿主 src/styles/index.css */
@import '@yd/ui/core/styles/tokens.css';      /* 库：令牌 */
@import '@yd/ui/core/styles/base.css';        /* 库：基础层 */
@import '@yd/ui/core/styles/components.css';  /* 库：控件配方 */
@import './fonts.css';
@import './tailwind.css';
@import './theme.css';
@import './demo1/layout.css';            /* 宿主：布局 */
@import './demo1/pages.css';             /* 宿主：页面 */
@import './demo1/animations.css';
```

**顺序不变式：库的控件配方必须仍在 `pages.css` 之前。**
原因：`pages.css` 里有大量**页面上下文覆盖**（形如 `.approval-actions .btn { … }`），它们依赖「写在后面才生效」。
顺序反了会静默出现外观变化，不会报错。

> 若 Vite 对 CSS `@import` 的 alias 解析失败，改为在 `src/main.ts` 里按同一顺序显式 import 各 CSS 入口，效果等价。

### 3.2 主题：`data-theme` 挂在 `<html>` 上

| 项 | 约定 |
| --- | --- |
| 主题切换 | 只认 `<html data-theme="dark">`，**不认 `.dark` class** |
| 为什么 | `body` 的 `color: var(--text)` 只在声明时解析一次；主题若挂在 `body` 子元素上，`body` 自己拿到的仍是亮色值 |
| 令牌真源 | 库的 `theme/tokens.ts`（`lightTokens` 全量 + `darkTokens` 差量） |
| 样式产物 | `src/styles/demo1/variables.css` 由 `scripts/gen-tokens.mjs` 从 tokens 生成，**禁止手改** |

### 3.3 antd 主题桥（宿主责任，不是库责任）

宿主 `App.vue` 通过 `ConfigProvider` 把库令牌喂给 antd：

- 传入的是**真实色值**，不是 `var(--x)`——antd 需要在 JS 侧做算法派生，`var()` 传进去算不出来；
- 亮/暗切换时必须同时切 `algorithm`（`defaultAlgorithm` / `darkAlgorithm`），只换色值不换算法会导致暗色下栅格、阴影、边框仍是亮色体系；
- 桥的一致性由 `scripts/gen-tokens.mjs --check` 守住（令牌与 CSS 不同步即退出码 1）。

## 4. antd 的关系（P0-T6 结论）

**antd 保留，并作为本库的 `peerDependency`。**

依据：`ant-design-vue` 被 18 个文件直接引用（全部表单页），且 `main.ts` 全量注册了 `Antd`。
表单页的交互、校验、日期控件均构建在 antd 之上——「去 antd」是一件与抽组件库无关的独立工程，不应混进来。

| 项 | 决定 |
| --- | --- |
| `OverflowTooltip` | **沿用 antd `Tooltip`**。它的 rAF 合并 + ResizeObserver 溢出测量逻辑本身是对的，换自研浮层是另一件事 |
| 库 `peerDependencies` | `vue: ^3.4.0`、`ant-design-vue: ^4.0.0` |
| 库内 antd 用量 | 仅 `OverflowTooltip` 一处；其余 11 个组件零 antd 依赖 |
| 后续演进 | 若将来要减少 antd 依赖，优先替换表单页，不动本库 |

> 反过来说：库的**样式层**必须容忍 antd 的存在。`components.css` 里针对 `.ant-*` 的规则（暗色表单标签、复选框、Select 下拉等）属于「给 antd 上主题」，是库的一部分，不能当死代码删掉。

## 6. 违规检测

| 检查 | 手段 | 何时跑 |
| --- | --- | --- |
| 令牌与 CSS 不同步 | `node scripts/gen-tokens.mjs --check` | 每次提交 |
| 搬迁导致外观变化 | `p0-baseline.cjs` + `p0-baseline-diff.cjs` | 每次搬迁后 |
| 库内出现宿主依赖 | 静态搜索库源码中的 `@/` 与 `../shared` | P5 加锁阶段 |
| 样式加载顺序被改 | 比对 `styles/index.css` 的 import 序列 | P5 加锁阶段 |
