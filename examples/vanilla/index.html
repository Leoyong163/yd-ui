这一页在证明什么

组件库分两层：core（零框架）与 vue（12 个组件）。 这一页完全没有加载 Vue，也没有跑任何构建 —— 它只做了一件事： 用 <link> 引了 dist-lite/yd-ui.css，然后按类名拼 HTML。

之所以能做到，是因为库的一条硬约束：组件自身不带 <style>， 所有外观都写在 core/styles 的类名配方里。 于是「Vue 组件」与「手写 HTML」用的是同一份 CSS、同一套类名 —— 不存在两套视觉， 也就没有「改了一边忘了另一边」的漂移空间。

可复核：本页与文档站里 Vue 组件渲染出的同类名元素，计算样式逐属性一致。 校验脚本 scripts/vanilla-parity.cjs 会同时打开两页比对，不需要人工看。 
<!-- 全部依赖就这一行 -->
<link rel="stylesheet" href="./dist-lite/yd-ui.css">

标签页 tabs core 独有 · 无 Vue 组件

这是 core 层里唯一一个没有 Vue 组件对应的配方。 原因很实际：切换标签页在原生页面里通常交给后端路由 （/list?tab=2，整页重渲染），用不着 Vue 接管， 所以没有必要为它写一个组件。它的类名因此住在 core， 只有手写 HTML 这一侧能用到 —— core 是 vue 的超集，这一节就是证据。

这一层的类名只负责「长什么样」，不负责「有哪些语义」。 CSS 里没有任何 role、没有键盘方向键处理， 也没规定 .active 该由谁切换。 带完整 ARIA 与键盘交互的标签页属于 vue 层要解决的问题 —— 而这一层只保证：你按下面的结构拼，它就跟文档站里的样子一致。 
<div class="tabs">
  <button class="tab active">待我审批 <span class="tab-count">12</span></button>
  <button class="tab">我已审批 <span class="tab-count">38</span></button>
</div>

<!-- 当前项加 .active（同时决定下边框色与文字色）
     角标是可选的 .tab-count，选中时自动换配色
     结构固定三层：.tabs > .tab > .tab-count -->

交互怎么办：这一层为什么不含 JS

库的零框架层只有样式，一条 JS 都没有。这不是遗漏，是刻意的： 交互逻辑一旦进了 core，core 就不再零框架；而每个原生页面的交互需求又各不相同 （有的用原生、有的用 jQuery、有的是服务端渲染），库没法替它们决定。

弹窗开关
容器 hidden 属性 + 两三行事件绑定；或直接用 vue 层的 Modal。
折叠 / 树展开
用原生 <details>/<summary> 承载，类名照旧，零 JS。
分页翻页
静态按钮 + 后端路由（?page=2），或自行绑定事件。
提示浮层
溢出检测需要测量 DOM，属 vue 层的 OverflowTooltip； 原生可用 title 属性起步。
需要完整交互
引 vue 层：import { Modal } from '@yd/ui'， 样式仍是同一份，视觉不会变。

怎么查可用类名

不要凭感觉拼类名。这份契约是从 core/styles/components.css 真源生成的， 原生 HTML 作者、文档站、AI 助手读的是同一份。

schema/class-contract.json
机器可读契约：27 个家族 / 128 个类名 / 状态修饰语 / 状态词表 / 图标键 / 资产表 / 皮肤钩子
dist-lite/manifest.json
直引包清单：CSS 与 sprite 的哈希、图标 id 列表、资产文件名
core/styles/components.css
真正的样式真源（合并产物由它生成，勿手改产物）
编辑器的 AI 助手
见库根 llms.txt 与 ai/ 下的规则文件，里面给了类名白名单
